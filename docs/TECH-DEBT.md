## Notes (known behaviour, no action)
- **F-28:** system units accept only `name` and `position` on update; `factor_to_base` arrives as a scale-12 string and is trimmed for display.
- **F-54:** the dev server is PHP's built-in server (`composer dev` → `php artisan serve`, ADR-0012). On Windows it serves one request at a
  time, so deferred props load one after another; with `opcache.enable_cli=0` each request costs ~0.3 s, with `1` ~0.06 s (2026-10-14). The
  S-18 speed target depends on this. Since S-29 was closed as it stood (D-13, 2026-10-15), measuring it is go-live gap **K-4**
  ([STATUS.md](STATUS.md) §6.4); Phase 6 (S-27) measures speed on real catalogue sizes.
- **F-34:** PostgreSQL's `lower()` folds non-ASCII letters and SQLite's doesn't, so "Étiquette" and "étiquette" clash only on PostgreSQL
  (production behaves as intended; tests stay ASCII).
- **F-59:** on SQLite, adding a foreign key or `change()` rebuilds the table (drop + recreate). With rows present, the `nullOnDelete` keys
  that point at the rebuilt table fire (S-44-a: `materials.created_by` became null after a `down()`/`up()` round trip with data) and
  `restrictOnDelete` keys would throw. PostgreSQL alters in place, so dev and production are unaffected; it only matters for migration tests
  that run with data on SQLite. (Moved here from Scheduled when S-44 closed; keep it in mind for S-53 if it adds a key to `stock_movements`.)
